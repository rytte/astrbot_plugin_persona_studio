<a id="tools"></a>

## 模型工具

每个操作使用独立工具，参数直接提交，不传入 `action` 或 `payload`。工具声明和执行校验共用同一份操作契约，只接受当前工具对应的字段；未知参数明确报错，并返回允许、必填、多余和缺少的字段，不忽略字段、不猜测操作、不自动重试。

旧的 `persona_manage`、`persona_versions` 工具已移除，不提供兼容别名。升级后重启 AstrBot 以重新注册工具；若人格的 `tools` 是显式名称列表，或系统提示词指定了旧工具名，需要手动替换为所需的新工具名。`tools=null` 仍表示全部可用工具，不需要修改。旧备份中的工具名称也不会自动迁移：包含已移除工具名的快照会明确拒绝恢复，可以查看历史内容后按新工具名称重新创建或更新人格，不要直接修改备份文件。

### 当前人格

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `persona_list` | 可选 `offset`、`limit` | 先按权限过滤再分页 |
| `persona_get` | `persona_id`，可选 `format`、`content` | 默认仅发提示词图片；形式与内容独立选择 |
| `persona_create` | `persona_id`、`system_prompt`；可选内容与能力字段 | 新建并绑定真实创建者 |
| `persona_update` | `persona_id`、至少一个内容或能力字段 | 先保存快照，再更新指定字段 |
| `persona_delete` | `persona_id` | 先检查引用并保存快照，禁止强删和自动解绑；返回 `backup_id` |
| `persona_switch` | `persona_id` | 只切换 AstrBot 分配的当前会话，保留历史，下一次新建的聊天请求生效；当前整个工具调用链不变 |

内容字段：`system_prompt`、`begin_dialogs`、`custom_error_message`；能力字段：`tools`、`skills`。不提供改名、任意会话 ID、发送目标或文件路径参数。未知参数明确报错。

`begin_dialogs` 必须是偶数条字符串，按用户、助手交替；清空传 `[]`。`system_prompt` 不能为 `null` 或空白，`custom_error_message=null` 用于清除自定义回复。精确 ID `default`、`[%None]`、`_chatui_default_` 不能新建。同名人格不覆盖、不自动改名。

删除检查全部配置（包含子代理）、历史对话绑定、强制会话规则及持久化任务；白名单用户只看到引用类型与数量，管理员可看引用位置。切换遇到强制会话规则或不存在的当前对话时拒绝，不修改规则、默认配置或其他对话；目标禁用管理工具时明确提示。

群聊 `switch` 沿用核心的 `unified_msg_origin`：共享群会话时切换该群当前对话，启用且支持群成员会话隔离时只切换对应成员的群内对话。不影响其他群、私聊或全局默认人格；群聊开关关闭后仍保留已经完成的切换，不自动恢复。

### 人格备份

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `persona_backup_list` | `persona_id`，可选 `offset`、`limit` | 查询全部可见版本链的备份及当前状态；人格已删除时仍可查询 |
| `persona_backup_get` | `backup_id`，可选 `format`、`content` | 历史详情使用相同查看选项，模型仍获得完整结构化原文 |
| `persona_backup_restore` | `backup_id`、`expected_revision` | 恢复任意保留快照，产生新版本 |
| `persona_backup_delete` | `backup_id` | 永久删除该备份，不删除或回退当前人格 |

用户明确要求删除备份且上下文已有真实 `backup_id` 时，直接调用 `persona_backup_delete`，例如参数 `{"backup_id":"b6e4bb4a-4826-48f0-9c2f-3f4e7260e953"}`。不需要查询列表，不传 `persona_id`、`expected_revision`、`format` 或 `content`。没有明确目标时先查询并确认，不能猜测要删除哪个备份。

`expected_revision` 是最新 `list/get` 返回的**不透明状态令牌**，不是旧快照的版本号；包含版本链和核心当前完整状态，恢复读取时已可见的 WebUI 修改或人格存在状态改变会使旧令牌失效，但不能阻止比较之后发生的外部并发写入。整数 `revision` 统计插件写操作，WebUI 写入不自动生成插件备份。

更新、删除及恢复已有记录前保存完整 JSON；备份写入失败就拒绝核心操作。删除后恢复保留原所有者和版本链，并绑定新的核心记录身份；同名的其他核心记录不能被旧备份覆盖。恢复只应用内容和能力，不恢复文件夹布局、会话、默认配置、子代理、任务或锁定状态。

删除备份不可撤销，不创建“备份的备份”。恢复和删除串行执行。保留策略每小时执行，也在写入和解锁后执行；锁定的版本链延后清理。过期、已清理及校验损坏的快照不能恢复，不承诺无限回退。

<a id="viewing"></a>

## 查看形式与内容

`persona_get` 和 `persona_backup_get` 共用以下选项，默认 `format=image`、`content=prompt`。每次只发送一种形式，不自动附加其他消息类型。

| 参数 | 取值 | 行为 |
| --- | --- | --- |
| format | text | OneBot/Aiocqhttp 与 Satori 使用合并转发，其他适配器发送普通文本 |
| format | image（默认） | PNG 图片，正文按文字行分页 |
| format | markdown | UTF-8 Markdown 文件，不需要浏览器 |
| content | metadata | 版本权限、人格信息、工具／技能范围、自定义错误回复及备份摘要 |
| content | prompt（默认） | 系统提示词和非空预设对话 |
| content | all | 元数据和提示词，先元数据后提示词 |

当前人格以 `persona_id` 定位，历史详情以查询返回的 `backup_id` 定位。例如 `persona_get`：

- 默认提示词图片：`{"persona_id":"澪"}`。
- 仅元数据图片：`{"persona_id":"澪","content":"metadata"}`。
- 查看文字提示词（按适配器选择合并转发或普通文本）：`{"persona_id":"澪","format":"text"}`。
- 导出完整 MD：`{"persona_id":"澪","format":"markdown","content":"all"}`。

`include_md` 已移除，继续传入将明确报错，不提供兼容分支。格式／内容只能使用上述精确枚举，不能传 `null` 或使用 `md` 等别名；选项只适用于 `get`。

- 图片的 `metadata` 只发送独立档案图；`prompt` 只发送正文图，不再自动附档案图；`all` 先档案图再正文图。档案字段解析成中文，不直接展示 JSON，时间统一标注 UTC；自定义错误回复仅归元数据，未设置显示“未设置”。
- 正文首页保留人格 ID 作为文档标题，但不再显示版本、锁定标签；续页仅保留淡色“接上页”、细线和底部页码。分页按首页／续页分别计算容量，避免切字并尽量保持标题与下一行相邻。能在单页容纳的表格行与代码块尽量保持完整，长代码块按实测文字行跨页；宽表格与长代码行自动换行，不使用截图中无法操作的横向滚动条。空预设对话不显示标题，独占一行的 `【小标题】` 仍加粗。
- 系统提示词和每条预设对话均解析 Markdown，支持标题、粗体、斜体、删除线、列表、引用、分隔线、链接、行内代码、代码块和表格；普通单换行保留为换行，空行按 Markdown 段落处理。公式、Mermaid 等扩展暂不渲染。只改变图片展示，人格存储、版本备份、文字输出和 MD 导出仍保留原文。
- 图片使用固定离线 HTML 模板；Markdown 禁用原始 HTML 并转义内容，图片语法仅显示“图片未加载”及替代文字，不读取网络或本地图片。禁用页面脚本并由浏览器会话拦截资源请求；仅图片依赖浏览器插件的隔离会话，不自行启动浏览器或关闭共享服务。所选图片总数受页数限制；档案保持单图，高度自适应但受像素上限约束；超限、超时或浏览器不可用时明确报错，不截断、不自动改形式。
- 文字按已核实的 AstrBot 内置适配器选择发送方式：`aiocqhttp`（OneBot v11）与 `satori` 已实现 `Nodes` 发送，使用合并转发；其他适配器直接发送普通文本，不要求机器人账号 ID。Satori 的实际转发效果取决于服务端与目标平台，插件无法从统一适配器接口探测其后端能力。
- 合并转发按元数据、系统提示词、每条预设对话组成节点，节点均使用机器人账号作为发送者；插件侧固定限制为每节点最多 4000 字符、总计最多 100 节点。普通文本保留相同内容与标题，每条最多 2000 字符。两种方式都优先沿换行分段并完整保留字符，不截断正文。超过转发节点上限时明确报错；发送失败不会再改发普通文本，避免重复发送。
- Markdown 按所选内容导出人类可读字段与原文，不包裹 JSON。默认仅含系统提示词和非空预设对话，元数据／完整内容仅在明确选择时加入。提示词附件名保留 `人格_<人格ID>_当前_v<版本号>.md`／`人格_<人格ID>_历史_v<快照版本号>.md`；元数据和完整导出在版本号后分别增加 `_元数据`、`_完整`。文件名保留中文，非法字符替换为下划线，UTF-8 总长不超过 200 字节；随机临时文件在消息提交后清理。
- 内容选择只影响展示和导出，不改变鉴权，模型仍收到完整结构化详情及发送回执。`delivery` 包含 `format`、`content`、`images_submitted`、`md_submitted`、`texts_submitted`、`forwards_submitted` 和 `forward_nodes_submitted`；`texts_submitted` 仅统计普通文本消息，转发与普通文本不会同时发送。平台回执仅表示已提交，不保证用户实际收到，发图也不表示模型已经看过图片。
- 渲染、导出及每次提交前后均重新检查真实调用者权限。部分发送失败明确报告已提交数量，不自动重试；权限撤销后停止后续提交并移除返回的结构化详情。写操作仍不自动回滚或重试。

默认只收到提示词图片是预期行为；需要档案请选择 `content=metadata` 或 `content=all`。缺少已选择的内容时，核对工具参数、`delivery` 回执和平台发送记录，不自动重复发送。

<a id="permissions"></a>

## 权限和保护

- 默认只有管理员可用；白名单用户只能管理自己通过本插件新建的人格及其版本，不能认领既有人格。
- 身份使用平台**实例 ID**与用户 ID，不是平台类型；创建者从真实消息事件自动绑定，模型不能修改所有者或白名单。
- 所有入口默认支持私聊和群聊；`allow_group_chat` 默认开启，设为 `false` 时仅允许私聊。模型工具及全部 `/ps` 命令在群聊中的鉴权与私聊一致。所有权仍绑定平台实例和真实发送者，不绑定群 ID；白名单是平台实例级授权，不是仅授权某个群。白名单变更每次调用重新读取；撤销授权后人格与备份保留。
- 群聊详情、图片、转发和文件直接发送到当前群，群成员可见；开启群聊即接受这项展示风险，不自动转私聊。
- 管理员和白名单用户均可配置内容、工具和技能：`null` 表示全部，`[]` 表示禁用，名称列表表示指定范围。创建时省略采用核心默认，更新时省略保持不变。
- 锁定禁止修改、删除、恢复以及备份删除，管理员也不能绕过；查看和有权限的切换不受影响。
- 白名单用户可解锁管理员锁定的自己的人格。锁定不是管理员封禁机制。

人工命令如下，没有备份查询、恢复命令：

```text
/ps lock <人格ID>
/ps unlock <人格ID>
/ps whitelist add <用户ID>
/ps whitelist remove <用户ID>
```

白名单命令仅管理员可用，目标固定为管理员当前平台实例的用户，不接受跨实例参数。变更保存到现有插件配置，与 WebUI 共用同一份白名单，立即生效且重启后保留；重复添加或移除不存在的用户只提示当前状态，不重复保存。保存失败时恢复内存配置并明确报错。移除不会删除人格、备份或改变所有者，也不撤销管理员身份；重新授权后可继续管理原有人格，人格锁定不阻止管理员变更白名单。

命令需直接来自真实私聊或已开放的群聊消息；拒绝原生消息缺失的合成命令事件，以及与原消息不一致的代调用。白名单管理不开放给模型工具。其他插件可直接修改核心或伪造事件，因此这不是不可信插件的安全沙箱。

<a id="configuration"></a>

## 配置参考

全部配置可在 AstrBot WebUI 的插件配置中调整，字段定义见 [`_conf_schema.json`](../_conf_schema.json)。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `allow_group_chat` | `true` | 是否允许群聊中的模型工具和 `/ps` 命令；`false` 时仅允许私聊 |
| `whitelist` | `[]` | 平台实例 ID 与用户 ID 组成的授权用户列表；管理员无需加入 |
| `max_personas_per_user` | `20` | 每位白名单用户可拥有的人格数，管理员不受此项限制 |
| `max_personas_total` | `200` | 核心中的全局人格数，包含通过 WebUI 创建的人格 |
| `max_prompt_chars` | `50000` | 单个人格的系统提示词字符上限 |
| `max_dialog_chars` | `50000` | 单个人格的预设对话总字符上限 |
| `max_error_chars` | `5000` | 自定义错误回复字符上限 |
| `backup_keep_count` | `50` | 每条版本链最多保留的备份数 |
| `backup_keep_days` | `90` | 备份保留天数 |
| `render_width` | `1000` | 详情图片宽度，单位为像素 |
| `render_page_height` | `1500` | 正文图片分页高度，单位为像素 |
| `render_max_pages` | `20` | 一次详情展示的图片总页数上限，包含档案图 |
| `render_max_pixels` | `2000000` | 单页图片像素面积上限 |
| `render_timeout` | `30` | 一次图片渲染的总超时，单位为秒 |

白名单配置示例如下，需将 `platform_id` 替换为实际的平台实例 ID，`user_id` 替换为授权用户 ID。平台实例 ID 不是 `aiocqhttp`、`satori` 等平台类型；使用管理员命令添加时会自动取当前实例。

```json
{
  "allow_group_chat": true,
  "whitelist": [
    {
      "__template_key": "user",
      "platform_id": "你的平台实例ID",
      "user_id": "123456789"
    }
  ]
}
```

群聊开关仅接受布尔值；已有配置明确保存的 `false` 不会自动覆盖，需手动开启。所有限额必须为正整数，未知配置字段或非法值直接报错。渲染配置还需同时满足：

- 宽度为 `480～1600`，正文分页高度为 `600～2400`。
- 宽度乘以正文分页高度不能超过 `render_max_pixels`。
- 总页数最多 `100` 页，总超时最多 `120` 秒。

人格内容字符上限与图片总页数是独立限制，允许保存的内容不保证能在默认页数内渲染，超限时需要管理员调整配置。

<a id="boundaries"></a>

## 数据和边界

`data/plugin_data/astrbot_plugin_persona_studio/studio.sqlite3` 保存归属、锁定、版本链、备份和审计，不保存额外的实时人格副本。不兼容旧配置或旧权限数据库；损坏时拒绝操作，不回退为开放访问。数据库含完整历史提示词，应仅授予运行 AstrBot 的账户读写权限，勿放入公开目录。

锁定**只约束本插件**，WebUI 和其他直接调用核心的代码不受插件锁定或所有权限制。同步只覆盖本插件实例，不能保证与 WebUI、其他插件或其他核心进程的写入互斥。核心数据和插件数据库不是分布式事务，失败可能留下可查询的快照或部分效果；不会自动补偿。

若通过 WebUI 删除锁定人格，历史版本链不会自动解锁，现有保护命令也不能解锁不存在的核心人格；需要随后恢复其历史版本时，应先通过本插件解锁再在 WebUI 删除。

删除引用检查是执行前的检查，不是覆盖所有配置、任务、会话绑定入口的全局引用事务；其他入口不应在删除过程中同时新增绑定。公开人格库的使用隔离也不在本插件保证范围内。

<a id="risks"></a>

## 已接受的核心风险

以下两项风险明确接受，本插件不修复，也不承诺对应的安全保证：

1. **WebUI 等外部入口的并发写入**：插件锁只串行化本插件实例的操作，无法阻止 WebUI、其他插件或其他进程同时修改人格。`expected_revision` 只能发现读取当前状态时已可见的变化，状态比较、备份与实际写入之间不是跨入口的原子操作。并发写入可能被插件覆盖，快照可能没有保存外部入口的中间更新，并发删除重建也可能使先前的记录身份校验失效。通过插件修改、删除或恢复人格时，应避免其他入口同时操作同一人格。
2. **指定工具可能绕过核心组件权限**：在本地验证的 AstrBot 4.27.4 中，`tools=null` 的全量工具路径使用权限包装，显式工具名称列表路径直接取得原始工具。若某工具仅依赖 WebUI 的“仅管理员”组件权限，内部没有再检查真实调用者，则白名单用户配置该名称后，非管理员的模型调用可能成功执行它。这不改变用户的管理员身份；本插件自身的人格与版本管理仍逐次鉴权，但不会替其他工具补查执行权限，也不额外禁止白名单配置管理员工具名称。白名单应仅授权可信用户，危险工具应在执行内部自行鉴权；后续核心版本的行为需另行核对。

## 开发验证

测试使用未修改的 AstrBot SQLite 和人格接口，并包含上述两项已接受风险的复现测试，不连接模型或聊天平台；本机存在 Chromium 时还会验证真实浏览器分页。需要测试环境提供 `pytest`、`pytest-asyncio`、`ruff`，以及核心和浏览器插件的依赖。默认从同级 `AstrBot` 查找源码，也可设置 `ASTRBOT_SOURCE`。

以下命令在插件仓库根目录执行：

```powershell
..\AstrBot\.venv\Scripts\python.exe -m pytest -q
..\AstrBot\.venv\Scripts\python.exe -m ruff check .
```
