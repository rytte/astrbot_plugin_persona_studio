# 人格捏造 · Persona Studio

让模型帮助你捏造、编辑和切换 AstrBot 人格，支持人工锁定、历史版本回退，以及完整详情图片与 Markdown 导出。

## 安装前提

- AstrBot 4.27 系列；本地验证版本为 4.27.4，无需修改主程序。
- 详情图片依赖已启用且就绪的 `astrbot_plugin_browser`；其他人格操作不依赖浏览器。
- 本插件没有额外的 Python 运行依赖，使用核心已提供的接口和标准库 SQLite。

本插件只使用核心已有接口，不修改主程序，也不在运行时替换人格管理器或工具执行器。

将本目录作为 `data/plugins/astrbot_plugin_persona_studio` 加载，随后在插件配置中填写白名单与限额。两个模型工具的核心组件权限应允许成员进入，实际准入及人格级权限仍由插件逐次校验。

## 已接受的核心风险

以下两项风险明确接受，本插件不修复，也不承诺对应的安全保证：

1. **WebUI 等外部入口的并发写入**：插件锁只串行化本插件实例的操作，无法阻止 WebUI、其他插件或其他进程同时修改人格。`expected_revision` 只能发现读取当前状态时已可见的变化，状态比较、备份与实际写入之间不是跨入口的原子操作。并发写入可能被插件覆盖，快照可能没有保存外部入口的中间更新，并发删除重建也可能使先前的记录身份校验失效。通过插件修改、删除或恢复人格时，应避免其他入口同时操作同一人格。
2. **指定工具可能绕过核心组件权限**：在本地验证的 AstrBot 4.27.4 中，`tools=null` 的全量工具路径使用权限包装，显式工具名称列表路径直接取得原始工具。若某工具仅依赖 WebUI 的“仅管理员”组件权限，内部没有再检查真实调用者，则白名单用户配置该名称后，非管理员的模型调用可能成功执行它。这不改变用户的管理员身份；本插件自身的人格与版本管理仍逐次鉴权，但不会替其他工具补查执行权限，也不额外禁止白名单配置管理员工具名称。白名单应仅授权可信用户，危险工具应在执行内部自行鉴权；后续核心版本的行为需另行核对。

## 权限和保护

- 默认只有管理员可用；白名单用户只能管理自己通过本插件新建的人格及其版本，不能认领既有人格。
- 身份使用平台**实例 ID**与用户 ID，不是平台类型；创建者从真实消息事件自动绑定，模型不能修改所有者或白名单。
- 所有入口仅私聊可用。白名单变更每次调用重新读取；撤销授权后人格与备份保留。
- 管理员和白名单用户均可配置内容、工具和技能：`null` 表示全部，`[]` 表示禁用，名称列表表示指定范围。创建时省略采用核心默认，更新时省略保持不变。
- 锁定禁止修改、删除、恢复以及备份删除，管理员也不能绕过；查看和有权限的切换不受影响。
- 白名单用户可解锁管理员锁定的自己的人格。锁定不是管理员封禁机制。

只有两条人工保护命令，没有备份查询、恢复命令：

```text
/ps lock <人格ID>
/ps unlock <人格ID>
```

命令需直接来自真实私聊消息；拒绝原生消息缺失的合成命令事件，以及与原消息不一致的代调用。其他插件可直接修改核心或伪造事件，因此这不是不可信插件的安全沙箱。

## 模型工具

### persona_manage(action, payload)

| action | payload | 行为 |
| --- | --- | --- |
| list | 可选 offset、limit | 先按权限过滤再分页 |
| get | persona_id，可选 include_md | 默认发完整分页 PNG；include_md=true 附 Markdown |
| create | persona_id、system_prompt；可选内容与能力字段 | 新建并绑定真实创建者 |
| update | persona_id、至少一个内容或能力字段 | 先保存快照，再更新指定字段 |
| delete | persona_id | 先检查引用并保存快照，禁止强删和自动解绑 |
| switch | persona_id | 只切换当前私聊，保留历史，下一次新建的聊天请求生效；当前整个工具调用链不变 |

内容字段：`system_prompt`、`begin_dialogs`、`custom_error_message`；能力字段：`tools`、`skills`。不提供改名、任意会话 ID、发送目标或文件路径参数。未知参数明确报错。

`begin_dialogs` 必须是偶数条字符串，按用户、助手交替；清空传 `[]`。`system_prompt` 不能为 `null` 或空白，`custom_error_message=null` 用于清除自定义回复。精确 ID `default`、`[%None]`、`_chatui_default_` 不能新建。同名人格不覆盖、不自动改名。

删除检查全部配置（包含子代理）、历史对话绑定、强制会话规则及持久化任务；白名单用户只看到引用类型与数量，管理员可看引用位置。切换遇到强制会话规则或不存在的当前对话时拒绝，不修改规则、默认配置或其他对话；目标禁用管理工具时明确提示。

### persona_versions(action, payload)

| action | payload | 行为 |
| --- | --- | --- |
| list | persona_id，可选 offset、limit | 查询全部可见版本链的备份及当前状态 |
| get | backup_id，可选 include_md | 历史详情图片、可选 Markdown、完整结构化原文 |
| restore | backup_id、expected_revision | 恢复任意保留快照，产生新版本 |
| delete | backup_id | 永久删除该备份，不删除或回退当前人格 |

`expected_revision` 是最新 `list/get` 返回的**不透明状态令牌**，不是旧快照的版本号；包含版本链和核心当前完整状态，恢复读取时已可见的 WebUI 修改或人格存在状态改变会使旧令牌失效，但不能阻止比较之后发生的外部并发写入。整数 `revision` 统计插件写操作，WebUI 写入不自动生成插件备份。

更新、删除及恢复已有记录前保存完整 JSON；备份写入失败就拒绝核心操作。删除后恢复保留原所有者和版本链，并绑定新的核心记录身份；同名的其他核心记录不能被旧备份覆盖。恢复只应用内容和能力，不恢复文件夹布局、会话、默认配置、子代理、任务或锁定状态。

删除备份不可撤销，不创建“备份的备份”。恢复和删除串行执行。保留策略每小时执行，也在写入和解锁后执行；锁定的版本链延后清理。过期、已清理及校验损坏的快照不能恢复，不承诺无限回退。

## 图片和结果

- 查看或“再发一下”人格详情需调用 `persona_manage(action="get", payload={"persona_id": "实际人格ID"})`；历史详情使用 `persona_versions(action="get", payload={"backup_id": "查询返回的备份ID"})`。工具自行发送图片，模型成功后只需简短确认，不应复述原文或另调 Markdown 渲染工具。
- 首张为独立的人格档案图，将版本、归属、锁定、时间、备份摘要和工具／技能范围解析成中文字段、状态标记与名称标签，不直接展示 JSON；时间统一按 UTC 展示并标注时区。
- 系统提示词和预设对话共用正文图，长内容按实际文字行分页。正文首页保留完整标题、人格 ID、版本和锁定状态；续页仅显示淡色“接上页”提示、细线和底部页码，不重复大标题及状态标签，并按精简后的页眉实际增加正文容量。空预设对话不渲染标题，未设置的错误回复不显示 `null`。提示词中的 `【小标题】` 会加粗，但原文与换行保持不变。
- 固定离线 HTML 模板，转义所有用户内容，禁用页面脚本；超出页数、像素或超时上限时明确报错，不截断、不静默改发文本。档案始终是一张图，高度自适应但受单图像素上限约束；总页数包含档案图。
- 不自行启动浏览器或关闭共享服务；通过浏览器插件的隔离会话测量并截图。
- 模型收到结构化人格原文及发送回执；图片发送不表示模型已经看过图片。平台回执仅表示消息已提交，不保证用户实际收到。
- Markdown 保存完整数据，附件名为 `人格_<人格ID>_当前_v<版本号>.md` 或 `人格_<人格ID>_历史_v<快照版本号>.md`，例如 `人格_澪_当前_v3.md`、`人格_澪_历史_v1.md`。保留中文，非法文件名字符及控制／格式字符替换为下划线，去除首尾空格和点，过长人格 ID 按完整 UTF-8 字符截短，文件名最多 200 字节；不改变正文中的原始 ID。临时文件使用随机名称，在消息提交后清理。
- 部分写入、部分发送失败不会误报完整成功，也不会自动回滚或重试；先查询现状再决定后续操作。

若只收到一张纯提示词图片，请核对本次是否调用了上述 `get`、返回的 `delivery.images_submitted`，并确认已更新、重载插件。当前 `get` 完整成功时至少提交两张图：档案图和正文图；未调用 `get` 时，通用 Markdown 渲染或模型复述不会自动补齐档案信息。提交数大于等于 2 但缺图时，需要继续检查平台发送记录，不要自动重复发送。

## 默认限额

全部可由管理员配置，正整数且非法值直接报错：

| 项目 | 默认 |
| --- | --- |
| 白名单用户人格数 / 全局人格数 | 20 / 200 |
| 系统提示词 / 预设对话总字符数 / 错误回复 | 50000 / 50000 / 5000 |
| 每条版本链备份数 / 保留天数 | 50 / 90 |
| 图片宽度 / 正文分页高度 | 1000 / 1500，按实测文字行避开切分 |
| 最大页数 / 单页像素面积 / 总渲染超时 | 20 / 2000000 / 30 秒 |

人格内容字符上限与图片总页数是独立限制，允许保存的内容不保证能在默认页数内渲染，超限时需要管理员调整配置。

## 数据和边界

`data/plugin_data/astrbot_plugin_persona_studio/studio.sqlite3` 保存归属、锁定、版本链、备份和审计，不保存额外的实时人格副本。不兼容旧配置或旧权限数据库；损坏时拒绝操作，不回退为开放访问。数据库含完整历史提示词，应仅授予运行 AstrBot 的账户读写权限，勿放入公开目录。

锁定**只约束本插件**，WebUI 和其他直接调用核心的代码不受插件锁定或所有权限制。同步只覆盖本插件实例，不能保证与 WebUI、其他插件或其他核心进程的写入互斥。核心数据和插件数据库不是分布式事务，失败可能留下可查询的快照或部分效果；不会自动补偿。

若通过 WebUI 删除锁定人格，历史版本链不会自动解锁，现有保护命令也不能解锁不存在的核心人格；需要随后恢复其历史版本时，应先通过本插件解锁再在 WebUI 删除。

删除引用检查是执行前的检查，不是覆盖所有配置、任务、会话绑定入口的全局引用事务；其他入口不应在删除过程中同时新增绑定。公开人格库的使用隔离也不在本插件保证范围内。

## 开发验证

测试使用未修改的 AstrBot SQLite 和人格接口，并包含上述两项已接受风险的复现测试，不连接模型或聊天平台；本机存在 Chromium 时还会验证真实浏览器分页。需要测试环境提供 `pytest`、`pytest-asyncio`、`ruff`，以及核心和浏览器插件的依赖。默认从同级 `AstrBot` 查找源码，也可设置 `ASTRBOT_SOURCE`。

```powershell
..\AstrBot\.venv\Scripts\python.exe -m pytest -q
..\AstrBot\.venv\Scripts\python.exe -m ruff check .
```
