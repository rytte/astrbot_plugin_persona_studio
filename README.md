# 🎭 人格工坊 · Persona Studio

在聊天中创造一个新人格，边聊边打磨，可以随时翻看旧版本。

`astrbot_plugin_persona_studio` 为 AstrBot 提供 **10 个模型工具**，支持人格创建、编辑、切换、历史恢复，以及图片、文字和 Markdown 文件展示。管理员可以直接使用，也可以授权可信用户管理各自创建的人格。

[功能一览](#features) · [安装与启用](#getting-started) · [聊天示例](#examples) · [模型工具](#tools) · [查看与导出](#display) · [权限与锁定](#permissions) · [使用与配置](./docs/使用与配置.md) · [开发验证](./docs/使用与配置.md#development)

<a id="features"></a>

## 🧩 能做什么

| 能力 | 使用方式 |
| --- | --- |
| 捏造与编辑人格 | 用自然语言描述角色，调整系统提示词、预设对话和自定义错误回复 |
| 配置工具与技能 | 为人格选择全部、禁用或指定名称的工具与技能范围 |
| 切换当前会话 | 保留聊天历史，下一次新建的聊天请求使用目标人格 |
| 查看与导出 | 生成分页提示词图片、发送文字，或导出保留原文的 Markdown 文件 |
| 保存历史版本 | 修改和删除前自动保存快照，恢复仍在保留范围内的历史内容 |
| 人工锁定 | 通过命令保护人格及其备份，模型无法自行解除锁定 |
| 按创建者管理 | 以平台实例和真实发送者绑定归属，白名单用户管理自己创建的人格 |

<a id="getting-started"></a>

## 🚀 安装与启用

### 1. 准备环境

| 项目 | 要求 |
| --- | --- |
| AstrBot | `>=4.27,<5`，本地验证版本为 `4.27.4` |
| 模型 | 在 AstrBot 中配置支持工具调用的模型，并为目标会话启用模型对话 |
| 图片展示 | 图片渲染依赖于 [浏览器服务](https://cloud.astrbot.app/plugin/rytte/astrbot_plugin_browser) 插件，可以从插件市场搜索安装 |
| Python 依赖 | `markdown-it-py>=4.0,<5`，见 [requirements.txt](./requirements.txt) |

### 2. 安装插件

在 AstrBot WebUI 的插件管理中，使用以下仓库地址安装：

```text
https://github.com/rytte/astrbot_plugin_persona_studio
```

也可以将完整仓库目录放入 AstrBot 的 `data/plugins/astrbot_plugin_persona_studio/`，然后重载插件或重启 AstrBot。

### 3. 开放使用权限

管理员默认可用。授权其他用户时，可以在插件配置的白名单中填写 **平台实例 ID + 用户 ID**，也可以由管理员在目标平台发送：

```text
/ps whitelist add <用户ID>
```

命令会自动使用管理员当前的平台实例，配置立即生效并在重启后保留。人格工坊模型工具的核心组件权限需允许成员使用，插件会在每次调用时继续校验白名单、人格归属和锁定状态。

<a id="examples"></a>

## 💬 试着这样说

按当前会话的唤醒方式与机器人交流，例如在群聊中先 @ 机器人。以下示例中的人格应由你创建，或属于你有权管理的范围。

| 想做的事 | 示例请求 |
| --- | --- |
| 创建人格 | “帮我捏一个叫‘澪’的人格，性格温和，喜欢天文，回答尽量简洁。” |
| 调整设定 | “把‘澪’的设定改一下：保留原来的性格，再加上喜欢用生活中的例子解释问题。” |
| 查看提示词 | “把‘澪’的提示词发成图片给我。” |
| 查看人格档案 | “看看‘澪’的归属、版本和可用工具，只发档案。” |
| 导出完整内容 | “把‘澪’的完整内容导出为 Markdown 文件。” |
| 切换人格 | “当前聊天切换到‘澪’。” |
| 恢复历史 | “列出‘澪’的历史备份，我选一个恢复。” |

切换会保留聊天历史，**从下一次新建的聊天请求生效**，当前整个工具调用链继续使用原人格和工具集。群聊共享会话时会切换该群当前对话；启用且支持群成员会话隔离时，仅切换对应成员的群内对话。强制指定人格的会话规则会阻止切换。

<a id="tools"></a>

## 🛠️ 模型工具

共 **6 个人格工具、4 个备份工具**，每个工具对应一个操作。

| 工具 | 简要说明 |
| --- | --- |
| `persona_list` | 分页列出当前用户有权访问的人格 |
| `persona_get` | 查看人格详情，支持图片、文字和 Markdown 文件 |
| `persona_create` | 创建人格，并绑定真实创建者 |
| `persona_update` | 修改人格内容、工具或技能范围，修改前保存快照 |
| `persona_delete` | 检查引用并备份后删除人格 |
| `persona_switch` | 切换当前会话人格，保留历史，下一次新建的聊天请求生效 |
| `persona_backup_list` | 查询人格的历史备份，人格删除后仍可查询 |
| `persona_backup_get` | 查看历史快照，支持与当前人格相同的展示形式 |
| `persona_backup_restore` | 恢复指定备份，并产生新版本 |
| `persona_backup_delete` | 永久删除指定备份，保留当前人格 |

参数直接提交给对应工具，完整参数与行为说明见 [模型工具参考](./docs/使用与配置.md#tools)。

<a id="display"></a>

## 🖼️ 查看与导出

当前人格和历史快照使用相同的查看选项，**展示形式与内容可以独立选择**。默认发送提示词图片，每次只发送一种形式。

| 展示形式 `format` | 效果 |
| --- | --- |
| `image`（默认） | PNG 图片，长正文按文字行分页，支持常用 Markdown 排版 |
| `text` | OneBot v11 / Aiocqhttp 与 Satori 使用合并转发，其他适配器发送普通文本 |
| `markdown` | UTF-8 Markdown 附件，保留提示词与预设对话原文 |

| 展示内容 `content` | 包含内容 |
| --- | --- |
| `prompt`（默认） | 系统提示词和非空预设对话 |
| `metadata` | 人格信息、归属、版本、锁定状态、工具与技能范围、自定义错误回复；当前详情还含备份摘要 |
| `all` | 先元数据，后提示词与预设对话 |

图片支持标题、列表、引用、表格和代码块等常用 Markdown 语法；公式和 Mermaid 暂不渲染，图片语法仅显示替代文字。图片展示不会改变人格中保存的原文。

例如，导出当前人格的完整 Markdown：

```json
{
  "persona_id": "澪",
  "format": "markdown",
  "content": "all"
}
```

上述参数用于 `persona_get`；查看历史时使用 `persona_backup_get`，将 `persona_id` 换为查询返回的 `backup_id`。详细分页、文件命名和发送回执说明见 [查看形式与内容](./docs/使用与配置.md#viewing)。

> 图片需要浏览器服务就绪，且受页数、像素和超时限制。生成失败会明确报错；需要文字或文件时，请显式选择对应形式。

<a id="permissions"></a>

## 🔐 权限与人工锁定

管理员可管理已有的人格；白名单用户只能管理自己**通过本插件新建**的人格及其版本，无法认领 WebUI 或其他入口创建的人格。所有者由真实消息事件绑定，模型不能修改归属或白名单。

人工命令负责锁定和授权：

| 命令 | 用途 | 谁可以使用 |
| --- | --- | --- |
| `/ps lock <人格ID>` | 锁定人格及其版本链 | 有权管理该人格的用户 |
| `/ps unlock <人格ID>` | 解除锁定 | 有权管理该人格的用户 |
| `/ps whitelist add <用户ID>` | 授权当前平台实例中的用户 | AstrBot 管理员 |
| `/ps whitelist remove <用户ID>` | 撤销该用户的白名单权限 | AstrBot 管理员 |

锁定后禁止修改、删除、恢复人格及删除备份，管理员也需要先人工解锁；查看和有权限的切换仍可使用。白名单用户可以解锁管理员锁定的自己的人格，因此锁定用于人工保护，不能作为管理员封禁手段。

移出白名单立即撤销插件访问权限，已有的人格、备份和归属会保留，重新授权后可继续管理。锁定和白名单维护只接受真实用户命令，未提供备份查询或恢复的人工命令。更多规则见 [权限和保护](./docs/使用与配置.md#permissions)。

<a id="versions"></a>

## 🗂️ 版本与恢复

修改、删除以及恢复已有的人格前，插件会先保存完整快照；备份失败时拒绝执行该次核心操作。删除前还会检查配置、子代理、对话绑定、强制会话规则与持久化任务中的引用，需要先通过有权限的入口解除引用。

恢复使用真实 `backup_id` 和最新备份查询返回的 `expected_revision` 状态令牌，并产生新版本。人格删除后仍可查询和恢复保留的快照，恢复时保留原所有者与版本链；同名的其他核心记录不能被旧备份覆盖。

备份按数量与天数保留，默认每条版本链最多 **50 份、90 天**，每小时及写入、解锁后执行清理，锁定的版本链延后清理。永久删除备份不可撤销，也不会改变当前人格。

全部 **6 个人格工具 + 4 个备份工具**、必填参数和恢复范围见 [模型工具](./docs/使用与配置.md#tools)。

<a id="boundaries"></a>

## 📌 使用边界

> [!WARNING]
>
> **本插件保留以下两项已知核心风险：**
>
> - **外部并发写入**：插件锁只约束本插件实例，WebUI、其他插件或进程的并发修改可能被覆盖，中间更新也可能未被备份。恢复令牌只能发现读取时已可见的变化，修改、删除和恢复时应避免其他入口同时操作同一人格。
> - **显式工具列表的权限路径**：本地验证的 AstrBot `4.27.4` 中，显式指定工具名称可能绕过核心组件的“仅管理员”包装。若工具内部未独立鉴权，白名单用户配置该名称后可能调用成功。本插件不补查其他工具的执行权限，也不额外禁止配置管理员工具名称；请仅授权可信用户，相关工具应在执行内部检查调用者权限。
>
> 复现条件与影响范围见 [已接受的核心风险](./docs/使用与配置.md#risks)，后续核心版本需重新核对。

归属、锁定、版本链、备份和审计保存在 `data/plugin_data/astrbot_plugin_persona_studio/studio.sqlite3`，数据库含完整历史提示词。插件锁定只约束本插件；核心人格数据与插件数据库之间没有跨库事务，失败可能留下快照或部分效果，写操作不会自动补偿或重试。完整说明见 [数据和边界](./docs/使用与配置.md#boundaries)。
